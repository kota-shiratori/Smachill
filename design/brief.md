# Smachill — UI デザインブリーフ（Claude Design 用）

そのまま Claude Design に投げるための指示書。
実装は Astro + Hono + D1（Cloudflare Workers）で進行中。API は動いていて、フロントだけが空。

---

## 0. 一文で

**テントサウナ1台を、AIとの会話だけで借りられるサービス。**
LP は「熱 → 冷 → 整」を追体験させる縦スクロールの作品で、その終着点にチャットがある。
カレンダーを埋めるのではなく、**話しかけると予約が終わっている**。

## 1. 作ってほしいもの

### フェーズ1 — トーン探索ボード（1枚）

**先にこれだけ出してほしい。** 方向性を決めてから画面を描く。

1枚のアートボードに、**対照的な3方向**を横に並べる。各方向につき:

- カラーパレット（背景・面・文字・アクセント・状態色）
- タイポグラフィ（日本語の見出し / 本文 / 数値。実際の日本語文で見せる）
- 同じパーツの見本 3点 — ①チャットのAI発話 ②「空きあり ¥38,000」のカード ③主ボタン
- 一言でその方向を説明するラベル

**ゼロベースで探る。** 既存プロトタイプ（§7）の色は参考であって縛りではない。
ただし全方向に共通で守ること:

- **日本語が主**。英語は補助ラベルまで。日本語で美しく組めない案は却下
- **明朝 / ゴシック / 等幅の役割分担を決める**。特に金額と日付は等幅・等幅数字（`tabular-nums`）
- **「熱 → 冷」の温度差がサービスの核**。何らかの形でパレットに温度の対比を持つ
- ダーク前提ではない。白基調・陽の光の方向も1案は見たい
- **テンプレSaaS禁止**。角丸カード＋青いボタン＋薄いグレー背景、Airbnb 模倣、絵文字装飾。どれも要らない

### フェーズ2 — 画面 6枚

トーンが決まったら、その1方向で描き切る。デスクトップ 1440 幅、最後の1枚だけモバイル 375 幅。

| # | 画面 | 主眼 |
|---|---|---|
| 01 | **LP（縦長1枚）** | 演出全開。章立てで温度を体験させる |
| 02 | **チャット / 空きあり** | 主導線。構造化カードの設計がここの本体 |
| 03 | **チャット / 空きなし → 代替提案** | 実は一番重要（§3-①） |
| 04 | **詳細入力 + 30分カウントダウン** | 静けさ。住所・氏名・オプション |
| 05 | **予約完了 / 予約詳細** | 「モノが旅してくる」ことを伝える |
| 06 | **モバイルのチャット（375幅）** | 実際はほぼ全員これで見る |

## 3. 普通の予約サイトにならない理由 — ここがデザインの根拠

### ① 在庫が1台。「空きなし」が通常状態

一般的な宿泊予約は「空いている日から選ばせる」。ここは**ほとんどの日が埋まりうる**。
だから **「その日は無理です」で会話を終わらせてはいけない。** 断りは必ず提案とセットで返す。

> 「9/20 からの2泊は埋まっています。**9/26 からなら空いています**。
> あるいは千葉ではなく東京なら、輸送が1日短いぶん **9/23 から**取れます。」

**この画面（03）が、このサービスのUIで一番おもしろい場所。** ここに一番時間を使ってほしい。

### ② 届け先の県によって、裏で塞がる日数が変わる

サウナは「モノ」なので輸送日も在庫を占有する。

```
千葉県（片道1日）で 9/20〜9/21 の2泊:
  9/19  出荷    ← この日もう他の人に貸せない
  9/20  利用
  9/21  利用
  9/22  返送    ← この日もまだ塞がっている
  → 客が使うのは2泊。個体は4日間ロックされる

北海道（片道3日）で同じ2泊なら 8日間ロック
```

ユーザーには見えない制約。でも**これを可視化できると、このサービスは他と違って見える。**

> 「あなたの2泊のために、サウナは 9/19 から 9/22 まで旅をします」

タイムラインなのか、地図なのか、伸び縮みするバーなのか — **表現を提案してほしい。**

### ③ 金額はサーバーが計算する。AIは計算しない

設計上の絶対規則: **AI（LLM）に金額を計算させない。** マスタから引いた値をサーバーが確定する。

これを **UI で表現する。** AIの地の文には金額を書かない。金額は必ず**確定値のカード**として、
会話とは異なる質感（面が立つ / 罫線 / 等幅数字）で提示する。

> 「千葉で2泊なら空いてます。内訳はこちらです ↓」
>   ┌────────────────────┐
>   │ 確定見積 ¥44,000 …  │  ← 別レイヤーの質感。これはAIの発話ではない
>   └────────────────────┘

**「AIが言ったこと」と「システムが確定させたこと」が視覚的に別物であること。** 信頼の設計。

### ④ 30分で消える

見積が出た瞬間から在庫が仮押さえされ、30分で解放される。
急かすUIは下品になりやすい。**焦らせずに、しかし残り時間が確かに減っていることを伝える表現。**
（残り5分を切ったときの見え方も描く）

### ⑤ 天候リスク

利用日が7日以内なら、天気の所見をAIが添える（`weather_note`）。
中止・延期の判断材料であって、警告バナーではない。**このトーンの置き場所を設計する。**

## 4. チャットUIの要件（02 / 03 / 06 の中身）

### 吹き出しだけのチャットにしない

AIが返すのは主に**構造化されたカード**。最低限これらを設計する:

| カード | 中身 |
|---|---|
| 空き判定 | 利用日・泊数・県・**片道日数**・占有される期間・可否 |
| 見積内訳 | 基本 / オプション / 送料 / 合計（§2の例のとおり） |
| 代替日程の候補 | 3案程度。それぞれ「なぜこの日か」の一言つき |
| 都道府県の選択 | 47個並べない。距離帯で束ねる |
| オプションの選択 | 会話の中で数量を増減できる。停止中のものは出さない |
| 仮押さえタイマー | 残り30分 |
| 天候の所見 | 7日以内のみ |
| エラー / 対象外地域 | 「配送対象外です」を突き放さない |

### 入力

自由文が基本。ただし空の状態で何を打てばいいか分からせないこと。
起点となるサジェスト（例:「9月の3連休、空いてる？」「北海道まで送れる？」「いくらくらい？」）を用意する。

### 状態

以下は**必ず描く**。ここを描かない設計は実装で必ず破綻する。

- 初回・空の状態（何を話しかければいいか分かる）
- AIが考えている / 返答がストリーミングされている途中
- 通信エラー・再試行
- 仮押さえが切れた後

## 5. LP（01）の要件

- **縦スクロール1枚**。章立てで温度を移動させる。参考の構成: 火入れ → ロウリュ（熱） → 水風呂（冷） → 整 → 予約
- 演出は**全開でいい**。WebGL 相当の重い表現を前提にしてよい（§6に実在するコンポーネント一覧）
- 大きな日本語の見出しで押す。説明文は少なく
- **最後は必ずチャットへ落ちる。** 「空き状況をチャットで聞く」が唯一の主CTA
- ただし LP と予約UIで**世界を切り替えない**。同じ作品の別の章として繋がって見えること

---

## 6. 予約UI（02〜06）の要件

**演出を落として静けさに寄せる。** 日付と金額を扱う面でノイズを立てない。
アクセントに微細な蒸気・粒子が残る程度。可読性が最優先。

**モバイル優先。** 川辺で・出先で・寝る前に触られる。片手で完結すること。

**`prefers-reduced-motion` 対応を前提に設計する**（動きを止めても情報が失われない構造にする）。

## 7. 既存の資産（参考。トーンは縛らない）

`~/dev/canvas-ui` に、同名のLPプロトタイプがある。**実験であって決定ではない。**

- React 19 + Vite + Tailwind v4 + shadcn/base-ui
- WebGL 演出コンポーネントが10種実在する:
  `Blaze`（炎・火の粉）`Clouds`（蒸気）`Liquid`（水面の歪み）`Frost`（曇りガラスが溶ける）
  `Grid`（面が波打つ）`Glitch` `Droplets` `Bubble` `ParticleReveal`（なぞった場所だけ像が戻る）
  `ParticleScroll`（スクロールで砂になって再結像）
- 現状のパレット: 背景 `#0a0806` / ember `#e8853b` / cold `#7fd4e0` / 蒸気 `#f0e7d8`、見出しは明朝、数値は等幅
- 章立て: 火入れ / ロウリュ / 水風呂 / 整（5連発）/ 予約

**「こういう演出が実装可能である」という技術的な事実として扱ってほしい。**
色・タイポ・レイアウトはフェーズ1でゼロから提案してよい。

⚠️ 一部の演出は Chrome のフラグ（`chrome://flags/#canvas-draw-element`）付きでしか完全動作しない。
**演出が動かなくても成立する構造**にすること。
