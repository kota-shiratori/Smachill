02 — なぜ Blaze の glow と smoke は死ぬのか
Blaze.tsx
Blaze.tsx:268 — 火のパス
outColor = vec4(fire,
  max(fire.r, max(fire.g, fire.b)));
アルファを色の明るさから作っている。明るい所は不透明、暗い所は透明になる。加算合成ではないので「暗闇に光を足す」方式ではない——だから明るい地でも火の粉そのものは不透明なオレンジの粒として乗る。
Blaze.tsx:265 — glow
vec3 glow = uSmokeColor * 0.05
  * uGlow * pow(1.0 - fy, 2.0);
係数が 0.05。既定の glow: 1.5 でも実効アルファは約 0.075。黒地なら燠火のもやとして見えるが、#FFF6EC の上では見えない。
!
smoke は原理的に直せない
明るい地で煙を見せるには地より暗い煙を描く必要がある。しかしアルファが明るさから作られている以上、暗い色を出すとアルファが下がって消える。パラメータをどういじっても出せない。shader をフォークして 1.0 - luminance をアルファにするなら可能。
合成パスは明るい地でも正しく抜ける
// Blaze.tsx:343
float luma = dot(content.rgb,
  vec3(0.299, 0.587, 0.114)) * content.a;
vec3 col = content.rgb * content.a
  * (1.0 - fire.a * luma) + fire.rgb;
HTML の内容を炎のアルファ × 自身の輝度ぶん削ってから炎色を足している。クリーム地は luma ≈ 0.95 なので、炎の濃い所は地をほぼ打ち抜いてオレンジになる。ここは明るい地のほうがきれいに抜ける。
結論
明るい地で火を見せるのは、光ではなく歪み。日中の焚き火が、炎そのものより陽炎で分かるのと同じ。distortion は背後を歪ませるだけなので地の色と無関係に効く。
03 — 明るい地の3原則
01
光ではなく影と歪み
暗い地の深度は「光を足す」で作れた。明るい地では飽和していて足せない。使えるのは shadow（Clouds）vignette（Droplets）shading（Grid）distortion（Blaze / Liquid）。既製のノブに全部揃っている。
02
少なくて濃い
黒地では不透明度5%の動きが見えた。クリームでは5%は見えない。だから「多くて薄い」ではなく「少なくて濃い」にしないと成立しない。逆に濃いものを多く置くと散らかる。節あたり1つに絞る。
03
重い演出は00〜03だけ
04物流 / 05料金 / 06流れ は白いカードが並ぶ面。日付と金額の上でノイズを立てない（ブリーフ §6）。E ではここを CSS の動きだけで持たせる。WebGL は上の4節に限定。
